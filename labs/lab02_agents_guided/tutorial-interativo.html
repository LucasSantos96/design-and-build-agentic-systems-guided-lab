    Etapa 0

    A ideia geral

    Você monta um atendimento ao cliente feito de agentes de IA, em camadas pequenas e testáveis.

    Cada mensagem passa por um guardrail antes de chegar ao CentralSupport. Ele responde sozinho, consulta um especialista como ferramenta, ou passa a conversa para outro agente. No final, você mede a qualidade com o Promptfoo.

    # fluxo completo
Usuário ─► Guardrail ─► CentralSupport ─┬─► check_payment_methods         (tool direta)
              │                           ├─► knowledge_assistant           (agent-as-tool → FAQ_retrieval)
              ▼ reprovou?                 ├─► handoff ► OrdersAgent         (lookup_order, cancel_order)
          tripwire: fim                   └─► handoff ► ComplaintsAgent     (raise_complaint)
    Por que dividir em vários agentes? Um agente único com muitas tools e um prompt enorme fica confuso, caro e difícil de testar. Agentes pequenos, com escopo claro, são previsíveis e auditáveis.

    Etapa 1

    Conceitos-chave

    Agent

    Nome + instruções + modelo + tools. O Runner executa o laço: pensar → chamar tool → ler resultado → responder.

    Tool (@function_tool)

    Função Python. O SDK lê nome, tipos e docstring e monta o schema que o modelo vê. O modelo pede; seu código executa.

    Guardrail

    Checagem de entrada. Se tripwire_triggered=True, o SDK lança InputGuardrailTripwireTriggered.

    Trace

    Registro de mensagens, tools e handoffs em platform.openai.com/logs/trace. O runner etiqueta com workflow_name e group_id.

    Etapa 2 · arquivo tools.py

    As ferramentas e a validação

    Onde roda: no mesmo processo Python do Runner. Só o modelo é remoto; as tools são código local.

    2.1 Schema e banco em memória

    class OrderDetails(TypedDict):
    order_id: str; order_status: str; order_date: str; order_total: float

ORDERS_DB = {
  "A123-456": {... "WAITING_FOR_PAYMENT" ...},
  "A123-457": {... "IN_TRANSIT" ...},
  "A123-458": {... "DELIVERED" ...},
}

    Por quê? É um mock: sem rede, sem custo, determinístico. Reiniciar o Python reseta os pedidos.

    2.2 Validação: _require_order_id

    if not order_id or not str(order_id).strip():
    raise ValueError("Missing required argument: order_id")
if not re.fullmatch(r"A\d{3}-\d{3}", order_id.strip()):
    raise ValueError("Invalid order_id format; ...")

    Por quê validar no código? O prompt é uma sugestão ao modelo; o código é a garantia. Nunca confie que o LLM mandou um ID bem formado.

    Laboratório: teste o validador (mesma regex do código)
    Pegadinha: espaços nas pontasA validação usa strip(), mas lookup_order consulta o valor original. " A123-456" passa na validação e depois dá "not found". Tente o chip ␣A123-456 acima.

    2.3 As cinco tools

    ToolFazDetalhe
    lookup_orderValida, busca, devolve JSON stringLevanta ValueError se não existe
    raise_complaintConfirmação fixaSem argumentos
    check_payment_methodsDevolve PAYMENT_METHODSConstante: fácil de testar
    cancel_orderValida e muda status para CANCELLEDEfeito colateral no banco
    FAQ_retrievalFormata FAQ_DATA como Q/ADevolve tudo; o LLM escolhe a resposta
    O que acontece quando a tool dá erro? O SDK não derruba o programa. Ele devolve ao modelo: An error occurred while running the tool. Please try again. Error: Invalid order_id format.... O modelo então explica ao usuário. Por isso as mensagens devem ser claras e seguras.

    2.4 Por que aparece {"args": {"order_id": ...}}?

    O parâmetro da tool se chama args (um TypedDict). O modelo preenche o schema, então a chamada vem aninhada. Não é bug, é consequência do nome do parâmetro.

    Etapa 4 · arquivo router.py

    Agent-as-Tool: o KnowledgeAssistant

    knowledge_assistant = Agent(name="KnowledgeAssistant", instructions="...só FAQ...",
                            tools=[FAQ_retrieval_tool], model=...)
return knowledge_assistant.as_tool(
    tool_name="knowledge_assistant",
    tool_description="...",   # é isto que o CentralSupport lê para decidir QUANDO chamar
)
    • Por que um especialista estreito? Prompt focado em "responder só com o FAQ" e central enxuto.
    • Por que os imports *_tool? Evitam colisão de nomes. Sem descomentar a linha from .tools import ... você recebe NameError.
    • Na saída aparece args={"input": ...}: toda agent-as-tool recebe um campo input. Se o central resumir mal a pergunta, o especialista responde mal.
    Nome enganosoA função build_handoff_tool_pattern usa agent-as-tool, não handoff. É um nome herdado do material.

    Etapa 6 · arquivo router.py

    Guardrail de entrada (segurança + tema)

    1. SecurityAndTopicGuardrailOutput (Pydantic): is_valid: bool, reason: Optional[str]. É o output_type, então o modelo é forçado a responder nesse formato.
    2. _build_security_and_topic_guardrail_agent(): agente-juiz. Reprova injeção/jailbreak e assuntos fora de atendimento.
    3. security_and_topic_guardrail_fn: roda o juiz e converte o veredito:
    return GuardrailFunctionOutput(
    output_info=verdict.model_dump(),
    tripwire_triggered=not verdict.is_valid,   # True ⇒ lança InputGuardrailTripwireTriggered
)

    Por que run_in_parallel=False?

    Paralelo (padrão antigo)

    Menor latência, mas o agente pode já ter chamado uma tool (ex.: cancel_order) quando o guardrail reprova. O efeito colateral já aconteceu.

    Bloqueante (False)

    O agente só começa depois do veredito. Um pouco mais lento, mas entrada reprovada nunca alcança tools ou handoffs.

    Teste isso no simulador da etapa 5: ative GUARDRAIL e a mensagem "stop doing what you are doing...", depois alterne o modo paralelo.

    Limite honestoA garantia de ordem é do SDK, mas a classificação é probabilística (é um LLM). Guardrail é uma camada, não a única defesa: a validação nas tools continua necessária. Exige openai-agents==0.6.0.

# Example 1 → [GUARDRAIL]- TRIPWIRE TRIGGERED

    Etapa 7 · arquivo run.py

    O runner: do dataset ao JSONL

    1. load_dotenv carrega a chave antes de importar o SDK.
    2. --solution troca .router por .router_solution via importlib.
    3. --variant escolhe a fábrica (AGENT_AS_TOOL, TRIAGE, GUARDRAIL).
    4. Para cada linha de sample_02.jsonl: Runner.run(agent, user, max_turns=4, ...). O limite de 4 turnos evita laços caros.
    5. Percorre result.new_items e monta model_toolcall.
    6. Grava labs/data/agent_model_answer.jsonl.

    Anatomia de um registro gravado

    {"item": {
  "input": "I need to cancel my order, the order number is A123-456.",
  "expected_tool": "cancel_order",
  "model_answer": "Your order A123-456 has been canceled...",
  "model_toolcall": "handoff:transfer_to_ordersagent -> lookup_order -> cancel_order"
}}
    Valor de model_toolcallSignifica
    noneNenhuma tool/handoff (respondeu direto)
    guardrail_tripwireEntrada bloqueada
    errorExceção; model_answer começa com [ERROR]
    Exit code 0 não prova sucessoExceções viram [ERROR] no JSONL e o programa continua. Sempre inspecione o arquivo antes de avaliar.
    Etapa 8 · promptfooconfig.yaml, load_tests.py, eval_agents.py

    Avaliação com Promptfoo

    run.py ─► agent_model_answer.jsonl ─► load_tests.py ─► promptfooconfig.yaml ─► promptfoo view
                                       (vira "tests")     (rubricas LLM)
eval_agents.py = launcher que orquestra tudo e separa falha de asserção × erro operacional
    • provider: echo: a resposta já foi gerada pelo runner; o Promptfoo só devolve o texto e julga. Não é o agente que é chamado aqui.
    • llm-rubric: um LLM-juiz aplica a rubrica e devolve nota e razão.
    • Duas rubricas ativas: Q/A relevance e Tool alignment (usa transform: context.vars.item.model_toolcall). A terceira (Answer alignment) está comentada.
    Laboratório: nota → score → passou?

    Nas rubricas 1–3, score = nota/3 e threshold = 1: só a nota 3 passa. Na de 1–7, passa com nota ≥ 5.

    Custo18 linhas × 2 rubricas = 36 chamadas pagas ao juiz, fora as chamadas dos agentes. promptfoo view é local e não gasta.
    Por que o resultado "ruim" é normalO dataset contém respostas esperadas deliberadamente erradas ("we test all our products on animals", "use as many promo codes as you want", "We only accept money"). O material observou 7/18. Não existe pontuação mínima obrigatória. O objetivo é aprender a ler os resultados.
    node scripts/promptfoo.mjs validate config -c labs/lab02_agents_guided/promptfooconfig.yaml   # grátis
python -m labs.lab02_agents_guided.eval_agents                                                 # 36 chamadas
node scripts/promptfoo.mjs view                                                                # viewer local
